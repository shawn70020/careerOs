01 / Product loop

不是履歷工具，
是改善循環。

CareerOS 的差異在於每次求職活動都會留下結構化資訊，並影響下一次履歷調整、學習優先序與面試準備。

01

建立職涯檔案

輸入真實履歷、經驗、作品與技能。

02

加入目標職缺

保存 JD、公司、職稱與求職狀態。

03

分析適配度

評估技術、經驗、遠端與作品支持度。

04

調整申請策略

產生定位、重點能力與履歷段落建議。

05

補足技能缺口

由目標職缺建立優先學習 Roadmap。

06

準備面試

根據 JD 產生技術、專案與行為題。

07

記錄面試回饋

保存卡點、回答、表現與最終結果。

08

更新下一輪

弱項回寫學習任務，下一次更精準。

03 / Product modules

七個模組，
共用一份職涯脈絡。

點選左側模組，快速理解它處理的問題、主要能力，以及在整個求職循環中的角色。

MODULE 01

Career Profile

所有 AI 判斷的真實資料來源。保存個人資訊、目標職位、工作經驗、專案與技能證據。

Onboarding履歷 → 目標角色 → 技能確認
Experience graph工作與專案分開建模
Skill levels熟悉度、年資與證據
Honest AI只強化真實經驗，不虛構經歷
MODULE 02

Resume Intelligence

把原始履歷轉成可分析、可版本化、可針對不同職缺輸出的申請素材。

Resume analysis摘要、優勢與弱項診斷
Version control保留語言、職位與關聯職缺
Tailored strategy定位、關鍵字與 bullet 建議
ExportPDF 與 Markdown
MODULE 03

Job Intelligence

不只追蹤申請狀態，也把 JD 轉成適配度、風險、缺口與下一步決策。

Pipeline從 Saved 到 Offer / Rejected
Fit scoring技術、經驗、英文、遠端與作品
Risk analysis辨識職務內容與偏好衝突
Skill gaps缺失技能自動成為 WeakArea
MODULE 04

Learning Roadmaps

學習不是通用課表，而是由目標職缺、現有能力與重複弱項共同決定。

Context-aware整合職缺報告與技能階段
Priority tasksCritical / High / Medium / Low
Practice prompts練習、面試題與下一步
Progress notes任務狀態與學習筆記
MODULE 05

Interview Feedback Loop

面試前依 JD 準備，面試後保存真實表現，再把弱項寫回學習路線。

JD preparation技術、專案、行為與遠端協作題
Interview logs階段、題目、回答與卡點
Weak areasAI 整理重複問題與嚴重度
Roadmap updates提高優先序或新增學習任務
MODULE 06

Career Dashboard

用一個頁面回答「我現在在哪裡、最重要的問題是什麼、下一步該做什麼」。

Job stats追蹤總數與申請中職缺
Resume score最近一次履歷分析分數
Active weaknesses高優先弱項集中顯示
Next learning當前 Roadmap 的待辦任務
MODULE 07

Public Demo Mode

讓訪客不需登入即可體驗穩定的 AI 結果，同時控制公開部署的 API 成本。

No login/en/demo 與 /zh-TW/demo
Mock AI本地預生成 JSON，結果穩定
Cost control避免公開 Demo 無限制呼叫模型
Portfolio-ready適合 Vercel 公開展示
04 / Data model

資料核心是 User，
不是 AI 對話。

系統保存的是可持續累積的職涯狀態。AI 只是分析與生成能力，真正的產品價值留在結構化資料與跨模組關聯中。

JobReports · Tailored Resume

WeakAreaSource · Severity · Status
AIRequestLogQuota · Result · Provider

資料設計原則

1
使用者資料隔離

主要查詢都帶入 userId，API 不能只靠物件 ID 讀取資料。

2
AI 結果可追蹤

分析報告、建議、弱項與 Roadmap 都保存進 PostgreSQL。

3
保留歷史版本

履歷、職缺報告與面試紀錄不只保存「最新文字」。

4
關聯形成回饋

職缺缺口與面試弱項能實際改變學習任務。

05 / AI workflow

AI 在服務層，
